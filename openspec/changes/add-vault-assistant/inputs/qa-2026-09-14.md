# Decisions with the owner (seed input, 2026-09-14, evening)

Secondary input, never groomed. It records the owner's answers to the open questions in
`brief.md` §8 and to the exploration that followed. It wins over the other seeds in this folder.

## Answers

| Topic | Decision |
| --- | --- |
| Plugin name | `vault-assistant`, not `meaningfy-assistant`: it manages a vault and a small daily routine, nothing like a general agent. |
| Bundle | A fifth, non-role bundle. |
| Scope | One change for the vault method and the daily routine. |
| Names | Every skill prefixed `vault-`, named like the rest of the catalogue. |
| Obsidian | The vault skills rely on the external Obsidian skills for syntax and file operations. |
| Sessions | Start and end belong to projects: `vault-resume <project>` starts, `vault-capture <project>` ends (and files raw notes any time). `close` is for finishing a project and archiving it. |
| Weather | Dropped; it has no method value. |
| Voice | Neutral and factual, attentive to attitude, implication and emotion where people write to each other. |
| Objectives | Plans live in `05 To Do/Objectives YYYY.md` with a change log at the end, not in Drive's history. |
| Planning | Weekly review widens into planning across day, week, month, quarter and year, OKR-friendly, with planning and review sessions. |
| Kinds | Start with a list and let it evolve. |
| `promote` | Kept; its behaviour is decided in the EPIC. |
| Setup | A `vault-setup` skill, like `project-setup`, that bootstraps the vault and its tooling. |
| Memory | Needs the company memory to be useful; document it. No cognee plugin. |
| Dual-CLI | Some opencode limitations are acceptable. |
| Daily | Owner leans to an agent on a schedule; decided in the EPIC (DEC-8). |
| Skills in the vault | No. |

## Drift to report upstream (`meaningfy-ws/infrastructure-stacks`)

- Skills renamed and merged: `create-project` and closing a project in `vault-project`;
  `session-start` becomes `vault-resume`; `capture-notes` and the old `close-project` (a session
  end) merge into `vault-capture`; `weekly-review` widens into `vault-planning`.
- Closing a project now sets `status` and proposes the archive move (upstream forbade both to
  `close-project`, which was a session end).
- The daily note has no weather; objectives move from `04 Daily/quarterly/` to `05 To Do/`.
- Resuming a project also reads `tasks.md` (the upstream requirement omitted it; its scenario needed
  it).
- The Obsidian CLI is allowed through the shell deny; templates are copied from `vault-setup`'s
  assets, then edited by hand.
- The daily routine ships with the vault method instead of after a week of use.
- A scheduled daily run is set up on the workstation (upstream: on demand only); the daily routine's
  stop rule is dropped.
- The voice comes from the company voice profile, not from example emails (`form: email`).
- Folder context stays in `AGENTS.md` and the skills; nested instruction files (a Claude Code
  mechanism) are not used. Moves go through the Obsidian CLI, not plain file tools.
- `resources.md` asks the owner for a file's web link when the Drive connector is denied, instead of
  requiring the link.
- Reviews move from `04 Daily/weekly/` to `04 Daily/reviews/`, covering week, month, quarter and
  year; the day stays `vault-daily`'s.
- `vault-setup` (new) writes the agent instruction and permission files, which a vault session may not
  edit; it therefore runs from outside the vault.
