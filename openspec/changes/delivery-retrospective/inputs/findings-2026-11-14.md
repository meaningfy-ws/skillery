# Findings — two weeks of Claude Code sessions (31 October to 14 November 2026)

> F-5, F-10 and F-11 are corrected in [`second-pass-2026-11-14.md`](second-pass-2026-11-14.md). The
> text below is left as first written.

**Status:** secondary input. Written on 2026-11-14, before the open test EPICs were read, so that
the comparison with them is not biased.

## How the numbers were made

`scripts/session_digest.py` reads the local Claude Code transcripts (`~/.claude/projects/`) and
writes three tables: sessions, subagents and a timeline of events. `scripts/epic_report.py` turns
them into per-epic tables and waste signals. Both run in under a minute over two weeks.

Three things to know when reading the numbers:

- **Cost per session is recorded** by Claude Code. **Cost per epic, phase or role is an estimate**:
  the session's cost is shared out by weighted tokens, and the price difference between models is
  ignored.
- **Phase is a guess.** It follows the last skill loaded in the session. About 9% of cost has no
  phase, and some build work is counted under shaping.
- **Nothing here comes from reading the transcripts closely.** These are signals from counts and
  timings. The cause is confirmed only where the text says so.

The most expensive skillery epics, as estimated shares of skillery's cost: test-strategy 17%,

## Where the time goes

Of 1,206 hours between the first and last record of each session:

| Kind of time | Hours | What it is |
|---|---|---|
| Person away | 673 | Gap between the end of a turn and the next prompt |
| Waiting on an answer | 94 | An open question to the person |
| Commands on the laptop, subagents | 83 | From tool call to result |
| Commands on the laptop, lead | 79 | Same, in the main session |
| Model, subagents | 53 | From request to last block of the response |
| Model, lead | 48 | Same, in the main session |

The rest is overlap and background waiting. Two limits: a permission prompt is counted inside its
command, and a `sleep` or polling loop counts as a command although nothing is computed.

**F-1. Elapsed time is mostly the person, not the agent.** About 64% of elapsed time is the person
away or answering. Of the agent's own time, commands take more than the model (162 against 101
hours).

## Where the tokens go

**F-2. The lead session is about half the cost.** Roughly 48% is spent by the main session and 52%
by subagents. Shaping alone is about 20% of all cost.

**F-3. In the lead, the cost is the context read again on every call.** By weight, 71% of the
lead's tokens are cache reads, 18% cache writes and 11% output. The lead made 16,400 Opus calls.
Half of the paid sessions grew past 300,000 tokens of context, and eight past 600,000.

**F-4. Every agent starts heavy.** A main session's first call carries 62,000 to 72,000 tokens
before any work, in every repository.

**F-5. Since 9 November every worker subagent starts 26,000 to 38,000 tokens heavier.** Confirmed
cause: commit `b27cef1` (lean-delivery, released in v3.12.0) replaced the tool allow-lists of the
implementer and the code-reviewer with "inherit the session's tools". The whole tool catalogue of
the session now goes into each worker.

| Worker | First call before | First call after |
|---|---|---|
| code-reviewer | about 22,000 | about 60,000 |
| implementer | about 52,000 | about 79,000 |

The same step shows in all repositories on the same dates. A worker makes 14 to 26 calls, and each
call reads this context again.

**F-6. In subagents, 40% of the weight is cache writes.** Each new subagent writes its starting
context once at the dearer write price. 1,204 subagents means 1,204 such writes; F-5 makes each one
larger.

**F-7. Review and verification are 53% of all subagents and about 22% of cost.** 640 of 1,204
subagents review or verify. Whether a review round found anything is not recorded anywhere, so its
value cannot be measured yet.

**F-8. `clarity-gate` was loaded 130 times, almost always by subagents.** One session loaded it 17
times, another 13. `epic-planning` was loaded 58 times.

**F-9. 66 prompts came after more than an hour away.** The cache has expired by then, so the whole
context is written again at the write price.

## Where the laptop time goes

**F-10. Polling loops run for about 22 hours.** 1,119 commands contain `sleep`, `until` or `while`:
748 in subagents (15.7 hours) and 371 in the lead (6.6 hours). Each poll that returns is also a
model call that reads the full context.

**F-11. Waiting on GitHub takes about 15 hours.** `gh pr merge` ran 209 times for 9.7 hours, and
`gh pr checks` 204 times for 4.9 hours.

**F-12. Reading with shell tools dominates the command count.** `sed`, `grep` and `cat` ran 18,500
times (18 hours). They are fast one by one; the cost is one model call each.

## What the traces can and cannot tell

**F-13. Langfuse already holds most context.** Repository, branch and working directory are on each
turn's root span. Subagent type and description, the token split and the skills loaded are traced.

**F-14. Langfuse holds fewer events than the transcripts.** For 7 to 14 November it has 19,300 model
calls against 29,900 in the transcripts, and 15,500 Bash calls against 24,600, although it records
some long turns twice. The plugin caps sending at five seconds. The cause of the gap is not
established.

**F-15. Four things are traced nowhere:** the phase, the stage or task number, the outcome of a
review, and the cost (Langfuse has no price for the current models).

## Recommendations

| # | Recommendation | Addresses | Expected effect |
|---|---|---|---|
| R-1 | Give the worker agents a tool allow-list again, or exclude the connector tools they never use. | F-5, F-6 | 26,000 to 38,000 fewer tokens per worker start and per worker call. The cheapest fix found. |
| R-2 | Measure what makes up the 62,000 to 72,000 starting tokens of a main session (instructions, skill listing, tool listing, memory) and cut the largest part. | F-4, F-3 | Lower cost on every call of every session. |
| R-3 | Keep the lead's context small: a fresh session per stage, and hand reading and command-heavy work to a worker. | F-2, F-3 | The lead is half the cost and its cost grows with context size. |
| R-4 | Replace polling with one background command and its completion notice, including for CI and merges. | F-10, F-11 | Removes about 37 hours of waiting commands and the model calls that go with them. |
| R-5 | Scale the number of review and verify subagents by appetite, and record what each round found. | F-7, F-15 | Shows which rounds pay; today none can be judged. |
| R-6 | Check why one session runs `clarity-gate` up to 17 times, against the limit the skill already sets. | F-8 | Fewer gate rounds in shaping, the largest phase. |
| R-7 | Before leaving a session for more than an hour, compact or close it. | F-9, F-1 | Avoids a full context rewrite on return. |
| R-8 | Prefer one longer-lived worker over several short ones for work on the same files. | F-6 | Fewer starting-context writes. |
| R-9 | Have the delivery skills declare phase, stage and review outcome in a form a tool can read. | F-15 | Removes the guesses in this report. |
| R-10 | Add model prices in Langfuse, and find why it holds a third fewer events. | F-14, F-15 | Makes Langfuse usable for this review. Until then the transcripts are the source. |
| R-11 | Give the scripts a durable home and run them when an epic is archived. | the whole | The review becomes routine. |

## Open

- The ten most expensive epics have not been read step by step. The split of each into what was
  done, in which order, is still owed.
- Whether the cause of a slow phase is a skill, the repository's instructions or the way the
  session was run is not settled for any finding except F-5.
- The command grouping is crude: a loop is filed under its first word.
- A subagent's final report is mostly not captured, because it goes back through a hand-back call
  the script does not read.
