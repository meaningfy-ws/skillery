# The inventory of checks

Every check the catalogue has today, one row each, with an id the matrix files cite. The scope is
`skills/` and the repository's own checks (trigger probes, agent Gherkin under `tests/features/`,
the `make validate` gates). The file describes and judges nothing: it records what exists, where
its rule lives and when it runs. A missing check is a `gap` row in a family file, never a row here.

The ids are numbered consecutively and grouped by family, in the order of the matrix files:
software 1-31, documentation 32-35, DevOps 36-57, UI 58-59, shaping 60-69, modelling 70-77,
architecture 78-85, generic writing 86-107, cross-cutting 108-143. The family a check sits in
is the one the matrix file cites it from. Owners are named as a path and its section, so each row
can be checked against its source.
