== Common questions

*Who decides?*::
The developer. Agents draft, recommend and carry out. The lead asks every question, with options
and a recommendation.

*Can an agent accept the work?*::
No. Agents verify; people validate (the scenario sign-off, the acceptance demo, the model review).

*Can an agent commit and merge on its own?*::
Only when the developer grants it for a named EPIC. See <<authority>>.

== Sessions

A *shaping session* turns a need into EPICs. An *epic session* delivers one EPIC, stage by stage,
each stage one PR. A *validation review* closes an iteration. What each leaves behind is in the
`epic-delivery` skill.

== The team

The main session is the *lead*: it is the only one that talks to the developer, and it commits. The
other members are briefed for one job each. The roles, and when each is used, are in the
`epic-delivery` skill.

== The loop of a stage

Prepare, build, challenge, decide and fix, check, merge. The loop scales with the EPIC's appetite:
a small EPIC gets one review pass, a large one the full set. The steps and the scaling table are in
the `epic-delivery` skill.

== Authority

By default, agents commit only with the developer's consent. The developer may grant more for one
named EPIC; the limits of that grant are in the `epic-delivery` skill.
