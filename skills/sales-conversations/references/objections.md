# Objections

This file owns the objection taxonomy, the one classification of objections in the catalogue, and the rules of the library. `sales-qualification` (value equation, *Risk and blame*) maps its objection drivers onto these five types and supplies the cover the answers use.

## Five types

| Type | Sounds like | First move |
|---|---|---|
| **Stall** | "Let me think about it", "send me something" | "What's your main concern?", then agree a dated next step |
| **Decision-maker** | "I need to ask X" | "What will X want to know?"; offer to prepare it, or to join the conversation |
| **Price** | "Too expensive", "no budget" | Anchor on the cost of doing nothing; offer the smaller first step on the ladder; never discount |
| **Product** | "Will it work for us?", "is it a toy?" | Proof: the closest reference, a demo on their data |
| **Risk** | "We can't take the risk", "what if you disappear?" | Cover: reference, partner, fixed price, reversible step, handover, backup staff. Guarantees only from the safeguard options of `semantic-consulting-coach` (`engagement-lifecycle`), after the owner's yes |

Agree first; never answer with "but". Tag each objection in the dossier with its type.

## The library

The library has one home: the `objection_library` note named in `sales-config.yaml` (see `sales-operations`).

- **Each entry**: the objection in the client's words · type · the answer that worked · the proof used · deal and date.
- **Who writes**: the agent appends entries after meetings and in the weekly review.
- **Who prunes**: the owner.
- The agent never edits this skill file to hold entries.
