# Route: FWC Execution

Work orders under a framework contract Meaningfy already holds, always with a partner (the framework's lead or consortium). Each order is a deal; the framework itself was won in Calls & Tenders.

| Stage | Typical agent work |
|---|---|
| Client need discovery | understand the new need; agree scope direction with the client and the partner |
| RfO received | check fit with the framework scope and our capacity; roles with the partner |
| Offer preparation | technical and financial offer with the partner; formal questions |
| Offer submitted & negotiation | answers on scope, price, timeline |
| Won – order signed | delivery starts |

Days to rot per stage: [`../assets/pipelines.yaml`](../assets/pipelines.yaml).

**Specifics**
- The reply date of a request for offer is an activity of type *Deadline*. Orders here are not starred: every request for offer under a won framework matters.
- Name the framework in the dossier; the request for offer is the paper process.
- A deal here with no request for offer for a long time may really be a prospect for a framework: propose moving it.
