# Git & Collaboration (Engineering Standard)

Human-readable canon for how we use Git/GitHub and set up dev environments. The **operational**
version — the one agents follow — is the `meaningfy-git-workflow` skill; this document narrates
the *why* and points to the rules.

## Why

Decentralised work (DVCS) plus a central platform (GitHub) only stays sane if history is
readable and reviews are cheap. The conventions linked below buy that.

## At a glance

Commits (Conventional Commits, company email), branches (GitFlow; never a commit-type prefix),
rebase and merge etiquette, pull requests and the free-tier GitHub limits: the
[`meaningfy-git-workflow`](../../skills/meaningfy-git-workflow/SKILL.md) skill.

## Dev environment

Editor plugins, auto-format on less-common stacks (RDF), WSL file placement and notifications:
[`meaningfy-git-workflow/references/dev-environment.md`](../../skills/meaningfy-git-workflow/references/dev-environment.md).

Commit/PR *mechanics* are delegated to the external `commit-commands` skill.
